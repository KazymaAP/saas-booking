## 2. Единая авторизация `/auth` (`app/auth/AuthCard.tsx`)

**Выбор роли** (кнопки-карточки): `Предприниматель` («Хочу сайт с записью», иконка Storefront), `Партнёр` («Привожу клиентов», UsersThree). Роль по умолчанию: `partner` если `?role=partner` или есть `?ref=`, иначе `entrepreneur`.

**Режимы:** `Вход` / `Регистрация` (`?mode=register`), `Забыли пароль` → `requestCodeAction` (код на почту через Supabase OTP) → `resetPasswordAction`.

**Поля:** имя (только регистрация), email, пароль (минимум 8 символов), код из 6 цифр. `?ref=PR-XXXXXX` — код пригласившего партнёра, привязывается при `createPartner()`.

**Действия (server actions):** `registerAction`, `loginAction`, `requestCodeAction`, `resetPasswordAction`.

**Результат входа:** партнёр → `/partner`; супер-админ → `/admin`; владелец бизнеса → `/{prefix}/{slug}/panel`; аккаунт без бизнеса → сообщение «Аккаунт есть, но заявка ещё не обработана».

## 8. Публичная форма записи (`BookingForm.tsx`)

Поля: услуга (`select` из активных услуг), дата (`DateStrip`, горизонтальная лента), время (`SlotPicker`), имя, телефон (маска `+7 (___) ___-__-__`), email, комментарий, чекбокс согласия с обработкой ПД (`PRIVACY_VERSION`). Кнопка отправки с `useOptimistic`. Валидация — `bookingFormSchema` (zod, те же правила на клиенте и сервере). Ошибки — `FieldError` с `aria-invalid` / `aria-describedby`, фокус на первое невалидное поле. Слоты подгружаются через `useSlots` + `AbortController`, prefetch при наведении на дату, skeleton при задержке > 300 мс.
